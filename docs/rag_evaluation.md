# RAG检索评估

## 评估目的

验证车辆评估报告生成前的准则检索是否能够把正确条款放入Top 3，并比较BM25、FAISS语义检索和RRF混合检索的实际效果。

## 数据集

- 知识库：10份公开资产评估准则
- 知识片段：278个
- 标注问题：15个，其中10个调参问题、5个独立测试问题
- 覆盖主题：市场法、报告内容、评估程序、价值类型、法律权属、委托合同和质量控制
- 标注方式：每个问题人工指定一个或多个可以直接支持答案的知识片段

测试问题保存在`data/rag/evaluation_questions.json`。当同一要求同时出现在基本准则和专项准则中时，允许多个正确片段，避免把等价证据误判为错误。

## 指标

- **Hit@3**：前三条结果中至少出现一个正确片段的问题比例。
- **Mean Recall@3**：每个问题的正确片段在前三条中被召回的比例，再对所有问题求平均。
- **MRR@3**：第一个正确片段排名倒数的平均值。正确答案越靠前，该指标越高。

## 加权Hybrid调参

加权RRF不直接比较BM25分数和余弦相似度，而是根据两套结果中的排名计分：

```text
融合分数 = BM25权重 / (60 + BM25排名)
         + FAISS权重 / (60 + FAISS排名)
```

脚本只使用10个调参问题比较四组权重。调参结果如下：

| BM25权重 | FAISS权重 | Hit@3 | Mean Recall@3 | MRR@3 |
|---:|---:|---:|---:|---:|
| 1.00 | 1.00 | 90.0% | 85.0% | 0.850 |
| 0.75 | 1.00 | 100.0% | 90.0% | 0.933 |
| 0.50 | 1.00 | 100.0% | 90.0% | 0.883 |
| 0.25 | 1.00 | 100.0% | 90.0% | 0.883 |

因此选择BM25 `0.75`、FAISS `1.0`，然后仅在5个独立测试问题上评估一次。

## 独立测试结果

| 检索方式 | Hit@3 | Mean Recall@3 | MRR@3 |
|---|---:|---:|---:|
| BM25 | 60.0% | 60.0% | 0.600 |
| FAISS | 100.0% | 100.0% | 0.867 |
| Weighted Hybrid RRF | 80.0% | 80.0% | 0.700 |

FAISS使用本地`bge-m3`生成1024维向量，向量归一化后通过FAISS `IndexFlatIP`计算内积；归一化向量的内积等价于余弦相似度。

本次独立测试中，FAISS在5个问题上都能把正确证据放入Top 3。加权Hybrid虽然在调参集上优于等权Hybrid，但在独立测试集上仍继承了部分BM25噪声，没有超过单独的FAISS检索。这说明Hybrid是一种需要验证的候选方案，不是必然更好的答案。

## 复现方法

确保Ollama正在运行并已安装`bge-m3`，然后执行：

```bash
python scripts/evaluate_rag.py
```

脚本先用调参集选择加权RRF权重，再在独立测试集上比较BM25、FAISS和加权Hybrid，并覆盖生成`data/rag/evaluation_results.json`。

## 当前限制

- 独立测试集只有5个问题，结论是项目当前版本的初步基线，不代表所有查询。
- 问题和知识库来自同一领域，尚未测试口语化、含错别字或跨条款推理问题。
- 已划分调参集和测试集，但测试结果已经查看，后续不能继续针对这5题调权重，否则会产生测试集泄漏。
- 后续应新增30至50个从未参与开发的问题，并增加无答案问题、引用正确率和生成内容忠实度评估。
